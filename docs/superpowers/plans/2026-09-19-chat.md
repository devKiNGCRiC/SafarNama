# Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Steps use checkbox syntax. This is a **lean plan**: each task lists files, exact interfaces and the exact test cases; the code is written test-first during execution.

**Goal:** One-to-one and group chat with photos, real-time delivery, unread counts, typing/presence, requests and blocking.

**Architecture:** socket.io on the Express HTTP server pushes events; REST endpoints do all mutations. Injectable `realtime` object so REST tests need no sockets.

**Tech Stack:** Node 24 ESM, Express 4, Mongoose 8, socket.io 4 (already a server dependency), multer + Cloudinary media service (from SafarGram), React 18, `socket.io-client` (re-added), SCSS. Tests: `node:test`, `supertest`, `mongodb-memory-server`, `socket.io-client` (server devDependency).

**Spec:** `docs/superpowers/specs/2026-09-19-chat-design.md`

## Global Constraints

- **Git:** the owner runs all git commands. Never run `git add/commit/push/rm`; print suggested commands at the end of each phase.
- Server style as in SafarGram: ESM, `AppError` + `catchAsync`, `verifyToken`, acting user = `req.user`, ids must match `/^[a-f\d]{24}$/i` (use `assertObjectId`), error shape `{ success:false, message }`.
- Cursor paging: `parsePaging`, `cursorFilter`, `toPage` from `Server/utils/cursor.js`; inbox 20/page, messages 30/page (max 50).
- Limits: text ≤ 2000; image JPG/PNG/WEBP ≤ 8 MB, one per message; group name 1-50; group 3-50 members; requester ≤ 3 messages while recipient pending; rate limits per user id: 60 messages/min, 10 group creations/hour.
- Media: reuse `createCloudinaryMediaService` (`Server/services/safargramMedia.js`) with folder override `safarnama/chat`; temp files always removed (`removeTempFiles`).
- Tests never touch the real database (`mongodb-memory-server`); helpers in `Server/tests/helpers/`.
- Client: API base + `http` from `client/src/config/api.js`; current user from `state.auth.user` (has `id`, not `_id`); SafarGram styling tokens; code lives in `client/src/features/chat/`.
- Windows/shell: write files containing regex backslashes or long content with the Write tool (long heredocs and inline `\` escapes break in this shell).

## PHASE A - One-to-one chat

### Task A1: Models and pure rules
**Files:** the three models; `services/chatRules.js`; test `tests/chatModels.test.js`, `tests/chatRules.test.js`.
**Interfaces (produces):**
- Models default-exported: `ChatConversation`, `ChatMessage`, `ChatBlock` (schemas per spec §3; unique sparse `directKey`; unique `{blocker,blocked}`).
- `directKeyFor(a, b): string` (`"<smaller>:<larger>"` of the two id strings).
- `initialStatusFor(requesterFollowsOrFollowed: boolean): 'active' | 'pending'`.
- `PENDING_MESSAGE_LIMIT = 3`.
- `usersAreConnected(aId, bId): Promise<boolean>` (either has the other in `Profile.following`).
- `blockState(meId, otherId): Promise<{ blockedByMe, blockedMe }>`.
**Tests:** model validation (type enum, text ≤ 2000, block uniqueness, `directKey` uniqueness), `directKeyFor` symmetry, `usersAreConnected` for follow in each direction / none, `blockState` both directions.

### Task A2: Serializer and realtime fake
**Files:** `services/chatSerializer.js`, `tests/helpers/fakeRealtime.js`; test `tests/chatSerializer.test.js`.
**Interfaces:**
- `USER_FIELDS = "username firstName lastName avatar"`.
- `serializeMessage(doc): MessageJSON`.
- `serializeConversations(convs, meId, realtime): Promise<ConversationJSON[]>` (adds `partner`, `unreadCount` via one grouped count query, `isRequest`, `blockedByMe`, `blockedMe`, `online` for direct partner).
- `createFakeRealtime()` → `{ emitted: [{ userIds, event, payload }], emitToUsers, onlineIds, setOnline(ids) }`.
**Tests:** unread count uses `lastReadAt`, ignores own and system messages; partner is the other user; request flag.

### Task A3: Direct conversations, inbox, requests, accept/decline
**Files:** `Controllers/chat/conversationController.js`, `Routes/chatRoutes.js` (`createChatRouter({ media, limits, realtime })`, default export uses real deps), `Middleware/chatLimits.js`; test `tests/chatConversations.test.js`.
**Routes:** `GET /conversations`, `GET /conversations/requests`, `POST /conversations/direct`, `GET /conversations/:id`, `POST /conversations/:id/accept`, `DELETE /conversations/:id/request`.
**Tests:** create direct with a connected user → both `active`; with a stranger → recipient `pending`, requester `active`; calling twice returns the same conversation (one row); cannot chat with self (400); unknown user 404; blocked either way 403; inbox only lists my `active`, newest first, paged; requests lists my `pending`; non-member `GET` 403; accept → active + emits `conversation:updated`; decline deletes chat and messages (+ optional block); only the pending recipient may accept/decline.

### Task A4: Messages (send, history, read) with photos
**Files:** `Controllers/chat/messageController.js`, `Middleware/chatUpload.js`; test `tests/chatMessages.test.js`.
**Routes:** `GET /conversations/:id/messages`, `POST /conversations/:id/messages`, `POST /conversations/:id/read`.
**Tests:** send text → 201, conversation `lastMessage`/`updatedAt` updated, `message:new` emitted to every other active member (and `pending` recipients), not the sender; empty text and no image → 400; text > 2000 → 400; image message uploads via fake media and stores `media`; non-image / 2 images → 400; temp files removed; requester 4th message while pending → 403; pending recipient sending → 403; blocked → 403; non-member → 403; history newest first and paged, members only; read sets `lastReadAt`, zeroes unread, emits `message:read`; rate limit → 429.

### Task A5: Blocks, unread total, people search, presence lookup
**Files:** `Controllers/chat/blockController.js`, `Controllers/chat/metaController.js`; test `tests/chatMeta.test.js`.
**Routes:** `GET|POST|DELETE /blocks[/:userId]`, `GET /unread-count`, `GET /users/search`, `GET /presence`.
**Tests:** block/unblock idempotent, cannot block self, list; unread total sums active chats only (not pending, not own); search by username prefix case-insensitive, ≤ 10, excludes me and anyone who blocked me, rejects short queries; presence returns only ids the fake realtime reports online, > 100 ids → 400.

### Task A6: Socket server and index.js
**Files:** `services/chatSocket.js`; modify `index.js`, `package.json`; test `tests/chatSocket.test.js`.
**Interfaces:** `attachChatSocket(httpServer, { origins }) → { io, emitToUsers(userIds, event, payload), onlineIds(ids), close() }`.
**Tests (real `http` server on port 0 + `socket.io-client`):** connection refused without token and with a bad token; accepted with a valid token; `emitToUsers` reaches only that user's sockets (two users, two sockets for one of them); `typing` relayed to other members, not the sender, and ignored for non-members; `presence:watch` answers with current status and emits `presence` on first connect / last disconnect; inactive user refused.
**Also:** replace `app.listen` in `index.js` with `http.createServer(app)`, attach the socket, pass `realtime` into `chatRoutes`, mount `/api/v1/chat`. Verify boot on a spare port (read-only smoke).

### Task A7: Client foundation
**Files:** `features/chat/api.js`, `socket.js`, `ChatProvider.jsx`, `utils/chatText.js` (+ tests for pure helpers such as day-separator grouping); `client/package.json` (`npm i socket.io-client`), `App.jsx` (provider).
**Interfaces:** `useChat()` → `{ connected, totalUnread, refreshUnread(), onlineIds: Set, watchPresence(ids), subscribe(event, handler) → unsubscribe }`; socket connects only when logged in and disconnects on logout.

### Task A8: Chat UI (one-to-one)
**Files:** `pages/ChatPage.jsx`, `components/{ConversationList,ThreadView,MessageBubble,Composer,NewChatModal,RequestsList,UnreadBadge,MessageButton}.jsx`, `chat.scss`; modify `App.jsx` (routes `/chat`, `/chat/:conversationId`, `/chat/with/:username`), `Navbar.jsx`, Profile actions.
**Behaviour:** two panes ≥ 1024 px else one pane; optimistic send with failure retry; live `message:new` append + auto-scroll unless the user scrolled up; mark read when the thread is open and visible; typing indicator (emit debounced); online dot; Chats | Requests tabs with accept/decline; composer disabled with an explanation when blocked/limit reached; upload preview for a photo.
**Verification:** eslint (no new errors) and `vite build`.

### Task A9: Phase A verification and checkpoint
Run all server and client tests, lint, build; smoke-boot the server on a spare port (401 without token on `/api/v1/chat/conversations`); print git commands; manual checklist (two browser profiles: chat between connected users, request flow, block, photo, typing, online dot, unread badge, reconnect after server restart).

## PHASE B - Group chat

### Task B1: Group create, rename, members, leave
**Files:** `Controllers/chat/groupController.js`; test `tests/chatGroups.test.js`; routes added to `chatRoutes.js`.
**Tests:** create needs a name (1-50) and 2-49 other distinct members (else 400); creator is admin, others `active` members; creates a system message; blocked relations (creator↔member either way) → 403; rename admin-only (403 for members), emits `conversation:updated`; add members admin-only, max 50, skips duplicates, blocked → 403, system message; remove member admin-only (cannot remove self via this path); leave (self) by member; last admin leaving promotes the earliest-joined member; last member leaving deletes chat + messages + media; removed/left users can no longer read/send (403) and no longer see it in the inbox.

### Task B2: Group behaviour in messages/serializer
**Tests:** sending in a group reaches all other members' rooms; unread counts per member; system messages excluded from unread; group `ConversationJSON` has `name`, members with roles, no `partner`.

### Task B3: Group UI
**Files:** `components/{NewGroupModal,GroupInfoModal}.jsx`; extend `ConversationList`/`ThreadView` (group title, member count, sender names on bubbles, system-message rows).
**Verification:** lint + build; manual checks (create group, add/remove/leave, rename, live updates for members).

### Task B4: Phase B verification and checkpoint
All tests, lint, build, smoke boot, git commands, manual checklist for groups.
